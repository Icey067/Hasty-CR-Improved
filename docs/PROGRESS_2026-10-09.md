## Engine changes (sim/)

- `Match.tower_level` (optional; default unchanged). Re-drive sets it to the
  match's card level. Without it, level-16 cards against level-11 towers
  ended every re-driven match in about a minute.
- **Elixir Collector / Elixir Golem elixir** (`sim/match.py`, `elixir_table`):
  the client's `ManaCollectAmount`, `ManaGenerateTimeMs`, `ManaOnDeath`,
  `ManaOnDeathForOpponent` were never read. Pump sides' elixir refusals
  4.0 -> 0.27 per match; others 0.02 -> 0.007. Units of `ManaOnDeath` and
  payout on expiry are marked as hypotheses in the code.
- **Start elixir 6** is measured (refusals in the opening 30 s: 30 -> 0) but
  applied only inside the re-drive and the row builder. The engine default is
  still 5000; changing it is the owner's call.

## Findings

- Corpus: 83.5% of matches have all 16 cards in our engine (Void, Rune Giant,
  Spirit Empress are the only missing cards). Frame check: 95.2% of troop
  plays land on the player's own half after rotation.
- Hand reconstruction: Clash Royale's queue is FIFO, so after four plays the
  hand is the deck minus the last four plays. Checked on 1,206 play rows: the
  played card was in the reconstructed hand every time.
- Re-drive endings agree with the recording about half the time (49.5% winner,
  2,000 matches) and the engine three-crowns far more often (579 vs 305).
  Per-card ranking in `reports/redrive_fidelity.md` is the fix list.
- **Harness error caught by a control:** the first re-drive passed no spell
  table to `Match`, so every spell did nothing, and the first ranking blamed
  Rocket, Earthquake and Poison for that. A direct check (spell on a crown
  tower: 0 damage for all eight spells) found it. Fixed; the ranking above is
  the corrected one.
- Spell crown-tower damage matches the client's `CrownTowerDamagePercent`
  (Rocket 23%, Fireball 25%, Log 13%, Arrows 20%). **Lightning dealt 0 to a
  crown tower**: `sim/spells.py` kept its PROJECTILE section (7 fields read)
  over the AEO that names it (6), so it loaded with radius 0. Fixed by merging
  the AEO's area fields when the chosen section has no radius; only Lightning
  changed among the 29 spells (radius 0 -> 3500, life 0 -> 1500 ms), and it
  now deals 265 to a level-11 tower, the client's value.
- Scraper: 16 workers drew 1,010 HTTP 429s in 17 minutes, which is what
  escalated Cloudflare to the checkbox. Next run: 4 workers, <= 1.5 req/s.

The ghost screen saturates: the ghost fires the real opponent's commands even
when the board no longer warrants them, a reactive agent punishes that, and a
replayed pro (which cannot react either) does not. It cannot separate good
checkpoints. The reactive screen - a fixed reference checkpoint playing the
real opponent's deck on the same matches - is the instrument from here on.

Search: the policy proposes its top 2 cards x 3 tiles, each is tried in a
RoyaleSim save/load copy for 3 s with no opponent plays (so the opponent's
hidden hand is never used), scored by tower swing + value head + 0.05 x
log-prior. +27 pp against the same reactive opponent on the same matches.

- **Live search is limited by what a rebuild loses.** The rebuilt battle
  (units as single spawns with card, team, position and hit points; tower hit
  points; clock; own deck order and elixir) keeps only ~7 of the 24 points
  search earns on the true copy. Lost in a rebuild: spells and projectiles in
  flight, attack timers, targets, deploy timers. That gap is the next search
  task, and it is measurable with this harness.
- **Outcome weighting did not help** (37.0 vs 40.3, inside the noise; pro
  agreement 63.7% vs 65.1%). Most 10 s windows carry no tower damage, so the
  weights are mostly noise. Recorded as a negative result; not used.

### Delay and delay compensation (300 matches unless noted, same opponent)

RoyaleSim models the real client's command delay (21-22 ticks). It must be
set BEFORE `Battle.reset`; set after, it silently does nothing (a delayed run
first came back identical match-for-match to an undelayed one).

| Hog seat, both seats delayed 21 ticks | Hog wins |
|---|---|
| `rs_hog`, no delay at all (reference) | 44.3% [38.8, 50.0] |
| `rs_hog`, delay 21, no compensation | 32.7% [27.6, 38.2] |
| + look ahead 21 on the true engine copy, enemy new units hidden | 60.0% [54.4, 65.4] |
| (same, without hiding enemy units: leaks hidden plays - invalid) | (65.7%) |
| + look ahead on a battle rebuilt from public observation | 25.0% [20.4, 30.2] |
| + extrapolate unit motion (no engine) | 37.3% [32.1, 42.9] |
| + hold while our own play is pending | 27.3% [22.6, 32.6] |
| + extrapolate + hold | 34.0% [28.9, 39.5] |
| + look ahead on a **shadow re-drive** of public plays (30 matches) | 6.7%; with real towers pinned 16.7% |

- The delay costs ~12 pp. Compensation is worth a lot **if** the future is
  predicted well: +27 pp on the true copy.
- Every public-only predictor tried so far is no better, or worse, than none.
  The shadow re-drive (`tools/rs_shadow.py`) replays the match so far from
  public plays; it tracks the real battle early on but drifts (opponent plays
  seen up to 0.5 s late and back-dated by an assumed 1 s deploy, a few placed
  outside the legal area after the unit moved, a Royal Ghost missing), and a
  drifted future misleads the policy badly. No way to correct a running
  RoyaleSim battle was found (no in-place state edits in the API).
- So the live bot should currently use **no** look-ahead and **no** search
  on a rebuilt state; the gain is real but not yet reachable from public
  information. Next attempts, each measurable with `--shadow`: unit matching
  between shadow and reality and dropping the shadow when they disagree;
  exact deploy times per card; reading spell casts and placement from the
  live reader rather than inferring them.

### The rebuild was dropping every evolved and hero unit - fixed

Diagnosis (12 test matches, 920 decision points): a battle rebuilt from the
visible state and run 21 ticks forward was missing 31.6% of the units that
already existed, and 98.5% of those were units the rebuild had classed as a
card's *children* and skipped. They were not children: they were evolved and
hero forms of the card's own unit (`Skeleton_EV1`, `MusketeerHero`,
`IceGolemiteHero`, `MinionHorde_EV1`, ...), whose unit type differs from the
base card's. Hog 2.6's own Skeletons, Musketeer and Ice Golem are often
evolved or hero, so the rebuild routinely lost our own defence. Fix
(`tools/rs_eval.py`, `rebuilt`): a unit whose type starts with the card's base
unit name is rebuilt as that card.

| Hog seat, same 300 matches, calibrated reference | before fix | after fix |
|---|---|---|
| delay 21 + look-ahead on the rebuilt battle (public only) | 23.0% | **47.0%** [41.4, 52.7] |
| no delay + search on the rebuilt battle (public only) | 43.7% | 45.7% [40.1, 51.3] |
| references: delay 21, nothing / no delay, nothing | 32.0% / 40.7% | |

**Public-only delay compensation now works: +15 pp over none**, and above the
undelayed baseline. Search on a rebuild is +5 pp, inside the noise.

| Hog seat (300, calibrated reference) | Hog wins |
|---|---|
| delay 21 + rebuilt look-ahead + rebuilt search | 41.7% [36.2, 47.3] |
| delay 21 + shadow look-ahead, after the same forms fix in `rs_shadow.py` | 26.0% [21.4, 31.2] |

Search scores its candidates on the present board and ignores the delay, so
stacked on the look-ahead it pulls the other way; and the shadow re-drive is
still worse than nothing. **Live configuration for now: rebuilt look-ahead
(`--lead -21`), no search.**
